# Implementation Plan: [config-tool] CT-2 Comment-preserving values.yaml round-trip

## Overview
Add `config-tool/internal/roundtrip`, a core package (no `net/http`, no key semantics) that
parses a `values.yaml`, holds it, applies edits and writes it back byte-identically apart from
the generated `# Generated by dsc-config …` header. The yaml.v3 encoder normalizes indentation,
quoting, folding and blank lines, so re-encoding a `yaml.Node` cannot meet the byte-identity
bar. The engine keeps the original source bytes and uses the yaml.v3 node tree (Line/Column)
only as an index. Every edit is a surgical byte patch, and every write is re-parsed and checked
before it is returned. The API is the one TECH_STACK names: `Parse`, `Classify`, `Merge`,
`Write`. CT-3 adds the classification on top.

## Decisions fixed by this plan (step agents must not re-decide)

- **Corpus.** The property test globs `k3s/*.yaml` at test time (17 files today; the subdirectories hold
  kubectl manifests, not chart values). It also covers `charts/data-space-connector/values.yaml` (4187
  lines) and `charts/trust-anchor/values.yaml`. The test fails when any of `provider.yaml`,
  `consumer.yaml`, `trust-anchor.yaml`, `provider-eidas.yaml`, `consumer-gaia-x.yaml` or
  `consent-provider.yaml` is missing, so a moved corpus cannot pass vacuously. The manifests
  under `k3s/*/` are covered by a "never damages" test: each one either round-trips
  byte-identically or is refused with `ErrMultiDocument`.
- **Corpus facts the code must handle.** Five k3s files have **no trailing newline**
  (`consumer.yaml`, `consumer-auth.yaml`, `dsp-consumer.yaml`, `provider-gaia-x.yaml`,
  `consent-trust-anchor.yaml`), and the output must keep that. None of the corpus
  files uses anchors or aliases, so anchors, aliases, merge keys (`<<: *x`) and tags are tested
  with fixtures in `internal/roundtrip/testdata/`. Block scalars (`|`, `>`) and flow
  collections (`[]`, `{}`, `[a, b]`) do occur in the corpus. `k3s/consumer.yaml` has
  **duplicate mapping keys**: `optionalClientScopes: []` directly followed by a second
  `optionalClientScopes: [...]` at lines 816/817 and 845/846. No other corpus file has any.
  yaml.v3 decodes such a file into a `yaml.Node` but refuses it with `Decode(&any)`
  ("mapping key … already defined"), so no step may decode a corpus file into `any`
  directly; see *Duplicate keys*.
- **Duplicate keys.** `Parse` accepts them and the file round-trips byte-identically. Helm
  reads values non-strictly, so the last occurrence of a key wins, and the engine follows that:
  `Lookup`, `Set` and `Merge` resolve a duplicated key to its **last** occurrence, and earlier
  occurrences are *shadowed*. A shadowed key/value pair is never edited, never a leaf in
  `Classify` and stays byte-equal. Wherever a tree is decoded to `any` (the write self-check, and
  tests that compare decoded trees), the code goes through one helper, `decodeValue(*yaml.Node)`.
  It deep-copies the node, drops every shadowed key/value pair from each mapping, then calls
  `Decode(&any)`. Alias targets stay reachable through `Node.Alias`, so a shadowed anchor still
  resolves.
- **One YAML document per file.** A stream with more than one document gives
  `ErrMultiDocument`. A single leading `---` is allowed and stays as it is. Trailing document
  markers are accepted. A marker line is `---` or `...` at column 0 with nothing after it but
  whitespace. The **tail** is the run at the end of the file made only of marker lines and
  blank lines, starting at its first marker line: `a: 1\n---\n`, `a: 1\n...\n`,
  `a: 1\n...\n---\n`. yaml.v3 decodes a trailing `---` as a second document; the tail is
  accepted only when that document is a single null scalar with an empty value and no
  comments, and no third document follows (`...` alone adds no document). The tail is kept
  byte for byte after the body, and inserts at the end of the body go before it. Any marker
  left in the body other than the single leading `---` gives `ErrMultiDocument`, e.g.
  `a: 1\n...\n# c\n`: an insert after it would start a second document. A second document
  with content or comments still gives `ErrMultiDocument`. Empty and
  comment-only files parse into an empty document. A UTF-8 BOM and CRLF line endings are kept,
  and inserted fragments use the line ending the file already has.
- **Header.** Rendered by `Header.Render()`. It is two comment lines plus one blank line:
  ```
  # Generated by dsc-config <tool-version> for chart <chart-version> from <profile> — profile hash <hash>
  # Keys under a "dsc-config:owned" marker are re-rendered on every save.

  ```
  An empty field drops its segment, e.g. `for chart <v>` when the chart version is unknown.
  The header names the tool, the chart version and the profile hash (US-7.1). On `Parse`, a
  leading block that matches this shape is split off the body. Anything else, including user
  comments right below the header, stays in the body. Line 1 is recognized by the prefix
  `# Generated by dsc-config `, line 2 by its exact text, and line 3 must be blank. A partial
  match stays in the body. The prefix and the fixed line are named constants.
- **Header bytes are kept, not re-rendered.** `Parse` stores the recognized header's **raw
  bytes** plus the fields parsed from line 1 on a best-effort basis (`Header()` returns them;
  fields that do not parse are empty, and the profile hash is split off at the *last*
  ` — profile hash `). `Write` emits the raw bytes unchanged unless `SetHeader` was called, and
  only then emits `Render()`. So `Parse`→`Write` is byte-identical even for a hand-edited header,
  one from an older field order, or a profile name that contains ` — `, and `SetHeader` replaces
  the old header instead of adding a second one.
- **Header, BOM and line endings.** A UTF-8 BOM is split off before header detection and is
  always written first, at byte 0; the header follows it, then the body. Header detection
  accepts LF and CRLF lines. `Render()` returns LF lines; `Write` converts a rendered header to
  the document's line ending (detected from the body, LF for an empty body). The expected output
  of `SetHeader(h)` + `Write` is therefore `bom + eol(h.Render()) + body`, never
  `h.Render() + input`.
- **Byte patches, not re-encoding.** `Write` = BOM + header + source body with the patches
  applied + tail. With no edits, the body is the source bytes unchanged.
- **Patch model.** There are two kinds of pending edit, and both are rendered only at `Write`:
  - A **replacement** covers the byte span `[start, end)` of one existing node's value and is
    keyed by that node's path. A second `Set` on the same path replaces the first (last wins).
    Two replacements whose spans overlap without being the same span give `ErrPatchConflict`.
  - An **insert group** belongs to one existing parent collection and sits at a zero-length
    offset (the insertion point from the rule below). It holds the new keys of that parent,
    each with a value tree. All new keys of one parent live in that one group, so two inserts
    at the same offset never collide. The group is rendered as one fragment with its keys in
    lexicographic order, regardless of the order of the `Set` calls.
  - **A new value for a path supersedes everything pending below it.** When a replacement or
    an insert-group entry is recorded for path P, every pending replacement on a strict
    descendant of P is dropped, and so is every insert group whose parent is P or lies below
    P. The new value fully defines that subtree. So `Set(a.b.c, 2)` (an insert under `b`)
    followed by `Set(a.b, "s")` writes only `b: s`, and a descendant scalar replacement
    followed by a replacement of its ancestor writes only the ancestor's value. The reverse
    order, ancestor first and then a descendant, edits the pending value tree (see *Edits below
    a pending value*). Both orders give the last-wins result that *Merge semantics* promises,
    also across successive `Merge` calls on one document (CT-4: profile render, then
    overrides). The no-op rule compares against the in-memory tree, which already carries the
    pending edits. A `Set` equal to that tree adds nothing and keeps the descendant patches
    that produce it.
  - An insert offset strictly inside a replacement span gives `ErrPatchConflict`. At equal
    offsets, a replacement that ends there is applied before the insert group that starts
    there. `Write` applies everything back to front by offset. Under the supersede rule, nested
    patches cannot arise, so `ErrPatchConflict` is a guard against span bugs and not a result
    of any `Set` sequence.
- **Edits below a pending value.** A key created by an insert, a parent created on the way, or a
  collection that a replacement installs has no source Line/Column, so it is never addressed by
  offset. It lives as a value tree inside its insert group or replacement, and a later `Set` whose
  path runs into such a value edits that tree, not the bytes. Examples: `Set(a.b, 1)` with `a`
  missing creates the group entry `a: {b: 1}`, then `Set(a.c, 2)` makes it `a: {b: 1, c: 2}`,
  rendered once as one `a:` block. `Set(x, map)` followed by `Set(x.y, v)` changes `y` inside the
  pending map. The in-memory node tree gets synthetic nodes (Line 0) for pending values, so
  `Lookup` sees every edit; a path resolving to a synthetic node is routed to the tree that owns
  it. `Merge` therefore produces the same bytes whether it sets a missing subtree key by key or
  as a single map.
- **Self-check on write.** After patching, `Write` re-parses its own output and compares the
  decoded tree (`any`) with the original tree after the same edits were applied to a deep copy
  of the node tree. Both sides go through `decodeValue` (see *Duplicate keys*). If they differ, `Write` returns `ErrPatchVerification` and no bytes.
  A wrong write is an error, never a file.
- **Value equality.** The synthetic node for a new scalar is built from its rendered text, with
  the tag yaml.v3 resolves for that text, so `float64(2)` rendered as `2` is an `!!int` on both
  sides of the self-check. The self-check and the no-op rule compare through one helper,
  `equalValue`: numbers are equal when their values are, whatever the int/float type (Helm
  decodes every number as float64), and NaN equals NaN. So `Set(port, 8080.0)` on `port: 8080`
  adds no patch.
- **Aliases.** A path that passes *through* an alias node is refused with `ErrAliasPath`, because
  editing it would also change every other user of the anchor. A path that *ends* at an alias
  leaf (`b: *a`, or `*a` inside a flow collection) may be set: the replacement covers the
  `*name` text and changes only that use; the anchor site and other aliases stay byte-equal.
  The no-op rule compares against the alias's resolved value, so a `Merge` whose value equals
  it keeps the alias. Anchors used for repetition (one domain on many lines) therefore
  survive a merge that does not change the value. Editing an anchored or tagged scalar
  (`&a foo`, `!!str 1`) keeps the anchor and the tag and replaces only the value text.
- **Merge keys are not resolved.** `Lookup` sees only a mapping's explicit children. In
  `m:\n  <<: *a\n  y: 2`, `Lookup(m.x)` for an `x` that comes only from `&a` gives
  `ErrNotFound`, so `Set` and `Merge` insert an explicit `x` under `m`, which overrides the
  inherited value. The no-op rule (an equal existing value adds no patch) compares against
  explicit children only, so an override equal to the inherited value still writes the key;
  a second `Merge` with the same overrides is then a byte-level no-op. `Set` on the value of
  `<<` gives `ErrAliasPath`, because replacing it would change what the mapping inherits.
- **Deterministic insertion.**
  - A new key is appended after the last child subtree of the parent mapping. That subtree ends
    where Step 3's scanner ends its last leaf (a block scalar's content, a multi-line plain or
    quoted value, a multi-line flow collection), so `#` lines inside a literal block are
    content. Only after that end, comment lines indented deeper than the sibling column belong
    to that last child and are skipped; the key goes before the first blank line, or comment
    line at or left of the sibling column, that follows. If the last child ends in a
    keep-chomped block scalar (`|+`, `>+`), its trailing blank lines are part of the value, so
    the key goes after them. When one save adds several keys to the same parent, they are
    ordered lexicographically. Missing parents are created on the way, and a null parent gains
    children (see below). A `Key` segment that runs into a non-null scalar or a sequence, in
    the source or pending, gives `ErrNotMapping`: `Set(a.b, 1)` on `a: 5` or after
    `Set(a, "s")`. `Merge` never hits it, because a map override on a scalar is a type change
    and sets the whole map on `a`.
  - Only mapping keys are created. A path with an `Index` segment that is out of range, or that
    runs below a parent that does not exist yet, gives `ErrNotFound`; CT-2 never appends to or
    creates a sequence item. `Merge` does not need it, because it replaces lists whole.
  - The indentation is the column of the siblings. A new nesting level uses the document's
    detected indent unit, which is the most common positive indent step, with 2 as the
    fallback. Sequences use the dash style the document already uses: `- ` at the parent's
    column or indented.
  - New maps are rendered with sorted keys. An empty flow value (`{}`, `[]`) or a null value
    (`key:`, `key: null`, `~`) that gains children is replaced by a block collection. A
    non-empty flow mapping or sequence on one line gets the new entry appended inside its
    brackets, in flow style. A flow collection that crosses lines is not appended to: the new
    key turns into a replacement of that collection with its merged value from the in-memory
    tree, rendered as in *Span of a replaced value*, and later `Set`s below it edit that
    pending value tree.
- **Value style on edit.** The original quoting style is kept when it can represent the new
  value: plain stays plain, `'…'` stays single, `"…"` stays double, and `|`/`>` keep their
  indicator and chomping. Otherwise yaml.v3's scalar encoding chooses the style for the new
  value. A plain multi-line scalar is supported (the chart's own `values.yaml` has one: the
  `acr` client scope's `description:` at lines 912-914). Its span is defined in Step 3, and an
  edit replaces the whole span with the new value at the original start column, as one plain
  line when plain can hold it and otherwise in yaml.v3's choice of style. The source's line
  breaks inside that value are not kept. An implicit null (`key:`), the chart's empty default
  and the most common edit, takes the new value as plain where plain can hold it; Step 3 defines
  its empty span. Only a span that fails the span self-check (Step 3) gives
  `ErrUnsupportedScalar`, so the scanner refuses to edit instead of guessing.
- **Span of a replaced value.** Replacing a collection, or changing a value's kind (scalar,
  mapping, sequence), never touches the key line's own decoration: the key, the anchor, and the
  whitespace and line comment after the value stay byte-equal (`admin: # maintainer`, chart
  `values.yaml` line 44). yaml.v3 does not give the value text's position directly: an anchored
  or tagged node sits at its `&` or `!` (`k: &a foo` gives 1:4), and an unanchored block
  collection sits at its first child on the next line (`k: # c\n  a: 1` gives 2:3). The span is
  therefore measured from the *value point*: the offset right after the `:` that follows the key
  node's span (Step 3's scanner), or right after the `-` of a sequence item, then past any anchor
  and tag tokens and the whitespace after each (also Step 3's scanner). A key line where no `:`
  follows the key's span (a complex `?` key) gives `ErrUnsupportedScalar`. The span has up to two
  parts:
  - the *inline part*: the value text that starts on the key line (or the `-` line), from the
    value point to the end of that text, before the whitespace and line comment that follow.
    For a literal or folded scalar it is the header (`|`, `>-`, `|2+`). For a flow collection
    it runs from the opening bracket to the matching closing bracket, honouring quotes and
    nesting, and may cross lines (`additionalContexts: [` at chart `values.yaml` line 2823,
    `scopeMappings: {` at line 2836). It is empty for a block collection, an implicit null, and
    a plain or quoted scalar whose text starts on a later line (the `acr` `description:`);
  - the *block part*, whole lines below the key line: for a block collection, from the line
    after the key line to the last line of the subtree, excluding following comment lines at
    or left of the key's column (or the `-` column for a sequence item); for a literal or
    folded scalar, its content lines as Step 3 scans them; for a plain or quoted scalar that
    starts below the key line, the lines from its first to its last text line, so a line
    comment on that last line goes with it. Otherwise it is empty and sits at the start of the
    line after the inline part's last line.

  A *compact* sequence item is one whose collection's first child sits on the `-` line
  (`- a: 1\n  b: 2`, `- - a`; about 150 lines of the chart's `values.yaml`). It has no inline
  and block split: its span runs from the value point to the end of its subtree, under the same
  comment exclusion. A scalar or flow replacement is written at the value point (`- s`), and a
  block replacement is rendered compact again: the first entry on the `-` line, the rest at the
  column of that first entry. `- &x\n  a: 1` is not compact, because its first child is on the
  next line.

  The new value goes inline when it is a scalar, an empty collection (`[]`, `{}`), or a
  collection replacing a non-empty flow collection (it stays flow). A flow collection that sat
  on one line is rendered on one line. One that crossed lines is rendered multi-line as JSON
  (`encoding/json` with `SetEscapeHTML(false)` and the detected indent unit, sorted keys), which
  is valid flow YAML: the closing bracket goes at the indentation of the line that holds the
  opening bracket, and the inner lines one unit deeper. Comments inside a replaced flow
  collection go with it, as in a block part. An inline value replaces the inline part and the
  block part is removed. Otherwise the new value is a block fragment that replaces the block
  part, and the inline part is removed together with the one space before it. A same-kind scalar
  edit is not affected by this split: it replaces Step 3's text span.
  So `k: v # c` → map gives `k: # c` plus the block lines, `admin: # maintainer` + list gives a
  new block list under the unchanged key line, and a block map → scalar removes the block part
  and inserts one space plus the value at the value point, as for an implicit null
  (`k: # c\n  a: 1` → `k: s # c`). An anchor always stays, so every alias keeps a target and
  resolves to the new value. A tag stays when the kind is unchanged (and, for a scalar, the new
  value decodes under it). Otherwise the removal widens back over the tag token and the
  whitespace after it, but never over the anchor, since e.g. `!!map` on a scalar does not
  decode. Inline text is preceded by one space only when the byte before it is not already a
  space, so `k: !!map` → scalar gives `k: s`, not `k:  s`.
  A `<<: *x` that uses an anchor whose mapping becomes a scalar no longer decodes; the write
  self-check refuses it with `ErrPatchVerification`.
- **Merge semantics.** `render(profile) ⊕ overrides`, and the override wins. Two maps merge
  recursively. Any other pair, including a type change, replaces the value span of that key. A
  `nil` override writes `null`; key deletion is out of scope.
  A map override that meets an alias to a mapping (`m: *base`) merges with the alias's resolved
  value, as Helm sees it. If the result equals the resolved value, nothing is written and `*base`
  stays. Otherwise `Merge` sets `m` to the merged map: the `*base` use is replaced by a block
  mapping (an alias leaf may be set, see *Aliases*), and the anchor site and the other aliases
  stay byte-equal. The expansion writes values, so aliases nested inside `base` are written out
  too. A direct `Set(m.x, …)` still gives `ErrAliasPath`, because it passes through the alias.
- **Classify is a surface only.** Classify does a structural leaf walk plus a pluggable
  `Classifier`. The default classifier returns `ClassUnknown` for every leaf, and CT-3 supplies
  the real one without changing the API.
- **Out of scope.** Owned/recognized logic (CT-3), rendering a profile (Epics 3/5), schema
  validation (Epic 6), the `dsc-config:owned` markers themselves (written when rendering
  lands), and the HTTP and CLI wiring for loading a file (CT-3/CT-4).

## Steps

### Step 1: Document model, Parse/Write without edits, header, corpus round-trip test and ADR
Create `config-tool/internal/roundtrip/`:
- `doc.go`: package GoDoc, one or two lines: a comment-preserving round-trip of a values.yaml
  via byte patches over the source.
- `document.go`:
  - `Document` holds the source body bytes, the yaml.v3 root `*yaml.Node`, the parsed
    `Header`, the line-start offset table (to map Line/Column to a byte offset; yaml.v3's
    `Column` counts runes, not bytes, so the mapping walks the line's runes), the line
    ending, a trailing-newline flag, the BOM flag, the raw header bytes, a header-replaced flag,
    the tail bytes and the pending edits (empty for now).
  - `Parse(src []byte) (*Document, error)` splits off the BOM and a recognized header, decodes
    with `yaml.NewDecoder`, splits off a tail (see *One YAML document per file*), and gives
    `ErrMultiDocument` if a second `Decode` yields any other document. A first `Decode` that
    returns `io.EOF` (empty or comment-only file) maps to the empty document.
  - `(*Document) Write() ([]byte, error)` returns BOM + header (raw, or rendered in the
    document's line ending after `SetHeader`) + body.
  - `(*Document) Header() Header` and `SetHeader(Header)`.
  - Sentinel errors are declared with `errors.New`.
- `header.go`: `Header{ToolVersion, ChartVersion, Profile, ProfileHash string}`,
  `Render() []byte`, a zero-value check (a zero `Header` writes nothing, so `Write` on a file
  without a header and without `SetHeader` is exactly the input), and the constants for the
  prefix and the fixed second line.
- `roundtrip_test.go`, as parameterized table/glob subtests:
  - **Corpus property test.** For each corpus file: `Parse` → `Write` == input, and
    `Parse` → `SetHeader(h)` → `Write` == `eol(h.Render())` + input (the corpus has no BOM).
  - **Idempotence.** `Parse(Write(x))` → `Write` == `Write(x)`; the header is not duplicated.
  - **Manifests under `k3s/*/`.** Each one is byte-identical or gives `ErrMultiDocument`.
  - **Header detection.** Exact match, partial match, a user comment directly under the header,
    a header in the middle of the file (not split off).
  - **Non-canonical headers survive.** A hand-edited line 1, another field order and a profile
    name containing ` — ` each round-trip byte-identically through `Parse` → `Write`; after
    `SetHeader` there is exactly one header, the rendered one.
  - **Edge cases.** An empty file, a comment-only file, no trailing newline, CRLF, BOM, a
    leading `---`, BOM + header, CRLF + header (detected, and `SetHeader` writes CRLF).
    Trailing markers: `a: 1\n---\n`, `a: 1\n---`, `a: 1\n...\n`, `a: 1\n...`,
    `a: 1\n...\n---\n` and `a: 1\n---\n...\n` round-trip byte-identically;
    `a: 1\n---\n# c\n`, `a: 1\n...\n# c\n` and `a: 1\n---\nb: 2\n` give
    `ErrMultiDocument`.
  - A native Go fuzz target `FuzzRoundTrip`, seeded with the testdata fixtures: for every
    input that `Parse` accepts, `Write` returns the input unchanged. The seeds run under
    plain `go test`.
- Fixtures under `internal/roundtrip/testdata/`: anchors, aliases, merge keys, tags, block
  scalars, flow collections, a multi-document stream, CRLF, BOM. Every fixture carries
  comments in head, line and foot positions.
- Corpus paths are resolved relative to the package directory (`../../../k3s`) with
  named constants. `internal/layering_test.go` already covers the new package, so it needs
  no change. Confirm that it passes.
- `.github/workflows/config-tool.yaml`: add `k3s/**`, `charts/data-space-connector/values.yaml`
  and `charts/trust-anchor/values.yaml` to both `paths:` filters, so a change to the corpus or
  to a manifest under `k3s/*/` re-runs the tests that cover it.
- `doc/adr/0013-config-tool-roundtrip-byte-patches.md`, status Proposed:
  - Context: the yaml.v3 encoder is not byte-faithful.
  - Decision: keep the source bytes, use the node tree as the index, write through byte
    patches with a self-check. The library choice of ADR 0009 is unchanged.
  - Alternatives rejected: re-encoding via `yaml.Node`, a hand-written YAML parser, and a
    line-based text editor without a parse tree.
  - Add a row for 0013 to the table in `doc/adr/README.md` and change "ADRs 0009 to 0012" to
    "0009 to 0013".

Acceptance:
- `go test ./internal/...` passes, `make lint` is clean, and every corpus file round-trips
  byte-identically, with and without the header.

### Step 2: Paths, leaf walk and the Classify surface
Read-only API that later steps and CT-3 build on. In `internal/roundtrip/`:
- `path.go`:
  - `Path` is a `[]Segment`, where `Segment` is either a mapping key or a sequence index;
    constructors `Key(string)` and `Index(int)`.
  - `Path.String()` prints `a.b[0]`. A key is quoted when it is empty or contains `.`, `[`,
    `]` or `"`: `a."x.y"`, `"x[0]"`, `""`. Inside quotes, `"` and `\` are escaped with `\`.
    Other keys, `<<` included, print bare and are read back literally. The output is stable
    and readable in a load report.
  - `ParsePath(string)` is the inverse of `String()` for every `Path`; malformed input (an
    unclosed quote, a bad index, an empty bare segment) gives `ErrInvalidPath`.
- `(*Document) Lookup(Path) (*yaml.Node, error)` gives `ErrNotFound` or `ErrAliasPath`. A
  duplicated key resolves to its last occurrence (see *Duplicate keys*).
- `classify.go`:
  - `Class` enum: `ClassUnknown` (zero value), `ClassRecognized`, `ClassOwned`, with
    `String()`.
  - `Leaf{Path, Node *yaml.Node, Line int, Class Class}`.
  - `Classifier func(Path, *yaml.Node) Class` and `DefaultClassifier`, which always returns
    unknown.
  - `Classify(doc *Document, c Classifier) []Leaf`.
  - The walk is in document order. A leaf is a scalar, an empty collection or an alias node.
    Aliases are not followed, and a merge key `<<` is one leaf. Anchored collections are
    walked once, at the anchor. Shadowed duplicate keys are skipped together with their
    subtrees.
- `decodeValue` (see *Duplicate keys*) lives in this step, because the leaf-count test needs it.
- Tests (table-driven):
  - Paths through mappings, sequences, flow collections, dotted keys and aliases.
  - `String`/`ParsePath` round-trip, including the keys `x.y`, `x[0]`, `a"b`, `a\b`, `a\"`,
    the empty key and `<<`, and malformed inputs that give `ErrInvalidPath`.
  - Leaf order and count on the anchor fixtures.
  - On every corpus file, `Classify` returns as many leaves as an independent recursive count
    over the tree from `decodeValue`, and every leaf path resolves through `Lookup`.
    `consumer.yaml` is a named case: it must not be skipped because `Decode(&any)` refuses it.
  - Duplicate keys, from a testdata fixture (`a: []\na: [x]\nb: 1`, plus a duplicated mapping
    key whose shadowed value holds an anchor that a later alias uses): `Lookup(a)` returns the
    second `a`, `Classify` reports only its leaves, and `decodeValue` gives Helm's last-wins
    map.
  - `Classify` passes a custom classifier's result through unchanged.

Acceptance:
- `Classify`, `Lookup` and `Path` are exported with one-line GoDoc.
- No edit capability yet. All tests pass.

### Step 3: In-place scalar edit via byte-span patches, with the write self-check
In `internal/roundtrip/`:
- `span.go`: the byte span of a scalar node's value text. yaml.v3 puts an anchored or tagged
  node at its `&` or `!`, so the scanner starts at the node's Line/Column offset and skips the
  anchor and tag tokens and the whitespace after each. Step 4 reuses this scanner for the value
  point and for key spans. Per style:
  - plain: ends before ` #` or at the end of the line, trimmed of trailing whitespace
    (spaces, tabs and `\r`). Inside flow collections it also ends at `,`, `]` or `}`. A
    block-context plain value continues over the following lines that are indented deeper
    than the owning column: the key's column, or for a sequence item the column of its `-`.
    The span ends at the end of the last such non-blank line, before the first comment line,
    the first line at or below the owning column, or EOF. A ` #` on a continuation line ends
    the scalar there; the comment after it is not in the span. Blank lines between
    continuation lines are inside the span; trailing blank lines are not.
  - implicit null (`key:`, `key:   # c`, an empty `- `): yaml.v3 puts the node right after
    the `:` or `-`, so the span is empty. An edit inserts one space plus the new value text at
    that offset, before any whitespace and line comment that follow, so `key:   # c` becomes
    `key: v   # c`. Without the space the result would be the single scalar `key:v`.
  - single-quoted: ends at the closing quote; `''` is an escaped quote.
  - double-quoted: ends at the closing quote; backslash escapes are honoured; the span may
    cross lines.
  - literal and folded: from the indicator through the last line indented deeper than the
    owning key, excluding trailing blank lines that the chomping does not own.
  - Each span is checked by decoding its own text: the value must equal `node.Value`, and the
    decoded nodes must carry no `HeadComment`, `LineComment` or `FootComment`, because a span
    that swallowed a comment still decodes to the same value and the write self-check compares
    trees without comments. A failure gives `ErrUnsupportedScalar`. An empty implicit-null span
    is exempt from decoding.
  - alias leaf: yaml.v3 puts the node at the `*` and its `Value` is the anchor name. The span
    ends at whitespace, or in a flow collection at `,`, `]` or `}`. A lone alias does not
    decode, so its check is that the span text equals `*` + `node.Value`.
- `edit.go`:
  - `(*Document) Set(path Path, value any) error`. The value is a string, bool, int, int64,
    float64 or nil. Maps and slices are added in Step 4.
  - The path must resolve to an existing scalar or alias leaf, or `Set` returns `ErrNotFound`
    or `ErrNotScalar`; Step 4 widens this.
  - The new text is rendered in the original style where that style can hold the value (see
    Decisions), otherwise from yaml.v3's encoding of a single scalar node. A block scalar
    keeps its indicator, chomping and content indentation.
  - The edit is recorded as a replacement (see *Patch model* in the Decisions), and the
    in-memory node tree is updated so that later `Lookup` calls see the new value. A second
    `Set` on the same path wins. The applier refuses overlapping spans with
    `ErrPatchConflict` as a guard, and Step 4 adds the supersede rule for ancestors.
- `Write` applies the patches back to front, then runs the self-check from the Decisions.
  Add `ErrPatchVerification` and `ErrPatchConflict`.
- Tests:
  - **Per-leaf property test over the corpus.** For every scalar leaf from `Classify` in every
    corpus file, `Set` a sentinel value of the same Go type and `Write`; a null leaf gets a
    string sentinel, since `nil` over a null is a no-op. Each file is a parallel subtest, and
    its leaves are split into parallel shards of a fixed size (a named constant, e.g. 100
    leaves). The chart's `values.yaml` alone has about 1600 leaves at roughly 25 ms each, so
    sharding keeps that file from serialising the run. Under `testing.Short()` only every Nth
    leaf (a named constant) runs, plus the named cases below. `make test` and CI run without
    `-short`, so they cover every leaf. Then check:
    - a line diff against the source touches only the leaf's own lines; a single-line scalar
      changes exactly one line;
    - the preceding `# --` comment lines and any trailing ` # …` line comment are byte-equal;
    - a re-parse yields the sentinel at that path and every other leaf unchanged.

    Leaves that return `ErrUnsupportedScalar` are counted and listed. The test fails if any of
    them is in `charts/data-space-connector/values.yaml`, because the chart's own file must be
    fully editable. The `acr` scope's multi-line `description` is an explicitly named case.
    So are the items of the duplicated `optionalClientScopes` in `consumer.yaml`: an edit
    changes line 817 (or 846), and the shadowed line 816 (or 845) stays byte-equal. The
    re-parse checks go through `Lookup` and `decodeValue`, never `Decode(&any)`.
  - **Style table (parameterized).** Plain → plain; plain → needs quoting; plain multi-line
    (two and three lines, with a blank line inside, followed by a comment line, at EOF) → one
    line at the original column; plain multi-line with ` # …` on a continuation line (the
    comment stays); a plain multi-line sequence item (`- foo` / `  bar`); a plain scalar in a
    CRLF file; `'…'`; `"…"` with escapes; `|`, `|-`, `>`, `>+`; scalars inside `[a, b]` and
    `{k: v}`; anchored and tagged scalars; a string that looks like a bool stays quoted.
    Non-ASCII rows, from a testdata fixture: a value after a key with an umlaut (`ä: x`), and
    the items of a flow sequence with non-ASCII items (`ä: [é, x]`). Implicit-null rows:
    `key:` → `key: v`, `key:   # c` → `key: v   # c`, an empty `- ` item, and `key:` at EOF
    without a trailing newline.
  - Numbers, through `equalValue`: `Set(x, float64(2))` writes `x: 2` and the self-check
    passes; `Set(port, 8080.0)` on `port: 8080` adds no patch; `Set(x, math.NaN())` writes
    `.nan`, and setting NaN again adds no patch.
  - Two `Set`s on one path: the second value is written. The patch applier, fed two
    overlapping spans directly (an internal test, since no `Set` sequence produces them), gives
    `ErrPatchConflict`.
  - Duplicate-key fixture: `Set(a[0], x)` on `a: [y]\na: [z]` gives `a: [y]\na: [x]`.
  - `Set` through an alias gives `ErrAliasPath`. Editing the anchor changes only the anchor
    site. Alias-leaf rows on `b: &a 1\nc: *a\nd: [*a, x]`: `Set(c, 2)` gives `c: 2`, and
    `Set(d[0], 2)` gives `d: [2, x]`; in both, the anchor site and the other alias stay
    byte-equal. `Set(c, 1)`, equal to the resolved value, adds no patch and keeps `*a`.
  - Determinism: the same edits on the same input give equal bytes.

Acceptance:
- "Editing one value changes exactly that line and leaves its `# --` comment in place" is
  asserted against the chart's `values.yaml` and the k3s files. All tests pass and
  `make lint` is clean.

### Step 4: Deterministic key insertion, collection replacement and Merge
In `internal/roundtrip/`:
- `insert.go`:
  - `Set` on a path whose key is missing inserts it, creating missing parents, under the
    insertion rule in the Decisions. Add `ErrNotMapping`.
  - `Set` with a `map[string]any` or `[]any` value renders a block fragment. Keys are sorted,
    and the fragment uses the detected indent unit, the detected sequence dash style and the
    file's line ending.
  - Replacing a non-scalar value, or changing a value's kind, replaces the span defined in
    *Span of a replaced value*: the key line's anchor and line comment stay. Comments inside a
    replaced subtree (in its block part) go with it; the GoDoc of `Set` says so.
  - Empty flow, null and non-empty flow parents are handled as described in the Decisions.
  - When the source has no trailing newline and an insertion lands at EOF, a line ending is
    written before the fragment and the file still ends without one.
  - Inserting into an empty document appends top-level keys at column 0.
  - New keys go into the insert group of their nearest existing parent, and paths below a
    pending value edit its value tree (see *Patch model* and *Edits below a pending value*).
- `merge.go`: `Merge(doc *Document, overrides map[string]any) error`. It does a deep merge
  through `Set`, visiting the keys in sorted order so that the patch order, and with it the
  output, is deterministic.
- Tests (parameterized):
  - **Adding a key twice from the same input gives the same bytes.** Two `Parse`+`Set`+`Write`
    runs are compared, and so are two `Merge` runs with equal overrides.
  - **Insert, then re-parse, then insert again with the same value** is a no-op at the byte
    level: setting an existing equal value adds no patch.
  - Insertion position next to commented-out examples (the `values.yaml` style) and next to
    foot comments. `Set(a.e)` on `a:\n  b:\n    c: 1\n    # d: 2\nx:` puts `e` after
    `    # d: 2`, which stays with `b`. A last child ending in `|+` keeps its trailing blank
    lines, and the key goes after them.
  - `Set(a[5])` with two items in `a`, and a path with an `Index` under a missing parent,
    give `ErrNotFound`.
  - Nested parent creation.
  - `Set(a.b, 1)` on `a: 5`, and after `Set(a, "s")`, gives `ErrNotMapping`; `Merge({a: {b: 1}})`
    on `a: 5` replaces `a` with the map.
  - A last child ending in a literal block with `#` lines,
    `a:\n  s: |\n    # not a comment\n    echo\nx: 1` with `Set(a.t, 1)`: `t` goes after
    `    echo`, and the block's content is unchanged.
  - Sibling ordering when several keys are added to one parent: `Set(p.b)` then `Set(p.a)`
    (reverse order) writes `a` before `b`, and both survive.
  - Edits below a pending value: `Set(a.b, 1)` with `a` missing, then `Set(a.c, 2)` gives one
    `a:` block with `b` and `c`; `Set(x, map)` then `Set(x.y, v)` changes `y` inside the
    pending map; a replacement with a map followed by a `Set` below it does the same. `Merge`
    of a missing subtree gives the same bytes as one `Set` of that subtree as a map.
  - A new value supersedes pending edits below it, on `a:\n  b:\n    x: 1\n`:
    `Set(a.b.c, 2)` then `Set(a.b, "s")` gives `b: s`; `Set(a.b.c, 2)` then
    `Set(a.b, map{y: 3})` gives `b` with only `y: 3`; `Set(a.b.x, 5)` then `Set(a.b, "s")`
    gives `b: s` (last wins, no `ErrPatchConflict`). Two successive `Merge` calls on one
    document, where the second changes the type of a subtree the first one edited, give the
    second's value, and the self-check passes.
  - `Set` of a list on the duplicated `optionalClientScopes` in `consumer.yaml` replaces line
    817 and leaves line 816 byte-equal.
  - Indent detection on 2- and 4-space fixtures and on both dash styles.
  - `{}` → block, `[]` → block, null → block, and appending into a non-empty flow mapping and
    flow sequence.
  - Type change from a scalar to a map and from a map to a scalar. Scalars whose text starts
    below the key line: `k:\n  long plain\n  text` → map gives `k:` plus the block, and → `[]`
    gives `k: []`; `k: |\n  x` → map gives `k:` plus the block, with no `|` and no content
    line left.
  - Key-line decoration survives a replacement: `users.admin` in the chart's `values.yaml`
    (`admin: # maintainer`, a block list) set to a new list keeps line 44 byte-equal;
    `k: v # c` → map gives `k: # c` plus the block; `k: # c\n  a: 1` → `"s"` gives `k: s # c`;
    `k: &x {a: 1}` with `y: *x` elsewhere, set to `{a: 2}`, gives `k: &x {a: 2}` and `y` resolves
    to it; `k: &x\n  a: 1` set to a scalar keeps `&x`; `k: !!str v` → map drops the tag.
  - Flow stays flow: `[a, b]` → `[c]` on the same line; `[]` → non-empty list becomes block;
    a block list → `[]` gives `key: []` with the line comment kept.
  - Multi-line flow, against the chart's `values.yaml`: `Set` of a new list on
    `additionalContexts` (line 2823) and a `Merge` that replaces `scopeMappings.mappings`
    (inside the flow map at line 2836) each rewrite only the bracketed span, as multi-line JSON
    at the documented indentation, and leave the `## --` comment above the key byte-equal; a
    `Merge` that adds a key to `scopeMappings` re-renders that flow map with the new key.
    A fixture `k: [\n  1,\n  2\n]  # c` set to a scalar gives `k: s  # c`.
  - Value point and tags: `k: # c\n  a: 1` and `k: &x # c\n  a: 1` → scalar give `k: s # c` and
    `k: &x s # c`; `k: !!map\n  a: 1` → scalar gives `k: s`; `k: &x !!str v` → map keeps
    `&x` and drops `!!str`; `k: !!str v` → `"w"` keeps the tag.
  - Compact items: on `l:\n  - a: 1\n    b: 2\n  - x`, `Set(l[0], "s")` gives `  - s`,
    `Set(l[0], map{c: 3})` gives `  - c: 3` with no `a`/`b` left, and `l[1]` stays byte-equal;
    `- - a\n  - b` with `Set(l[0], [c])` gives `- - c`; `- &x\n    a: 1` → scalar keeps `&x` on
    the `-` line.
  - An anchored map used by a merge key, `a: &x\n  p: 1\nm:\n  <<: *x`, with `Set(a, "s")`:
    `Write` gives `ErrPatchVerification` and no bytes.
  - Alias to a mapping, on `base: &b\n  a: 1\n  b: 2\nm: *b\nn: *b`: `Merge({m: {b: 3}})`
    gives `m:` with `a: 1` and `b: 3` as a block, and `base` and `n: *b` stay byte-equal;
    `Merge({m: {a: 1}})` is a no-op that keeps `*b`; `Set(m.b, 3)` gives `ErrAliasPath`.
  - No-trailing-newline file.
  - Empty document.
  - A top-level key inserted into `a: 1\n---\n` or `a: 1\n...\n` lands before the marker,
    which stays last.
  - Merge-key fixture `m:\n  <<: *a\n  y: 2` with `x` inherited from `&a`: `Lookup(m.x)` gives
    `ErrNotFound`; `Set(m.x)` and a `Merge` over `m.x` each insert an explicit `x` after
    `y: 2` and leave the `<<` line and the anchor site byte-equal; repeating the `Merge` on
    the output is a byte-level no-op; `Set(m.<<)` gives `ErrAliasPath`.
  - Merge over `k3s/provider.yaml` with a nested override tree: the diff contains only the
    overridden and added lines, and the re-parsed tree equals a reference deep merge of the
    decoded maps. The reference implementation lives in the test.

# 0013 - Round-trip values.yaml through byte patches over the source

**Status:** Proposed
**Date:** 2026-11-16
**Applies to:** the configuration tool (`dsc-config`), `FIWARE/data-space-connector`
**Context doc:** [`../config-tool/TECH_STACK.md`](../config-tool/TECH_STACK.md)

## Context

CT-2 (#117) must load a user's `values.yaml`, apply edits and write it back so that a diff
shows only the edits: every comment, blank line, quoting style, anchor and indentation stays as
it was, apart from the generated `# Generated by dsc-config …` header. The corpus is
`k3s/*.yaml` and both charts' `values.yaml`.

[ADR 0009](0009-config-tool-stack.md) fixes `gopkg.in/yaml.v3` and its node API for the
round-trip. The node tree keeps comments, but the yaml.v3 encoder is not byte-faithful: it
re-indents, re-quotes, re-folds long scalars, moves comments and drops blank lines. Re-encoding
a parsed `values.yaml` of the corpus does not give back the input.

## Decision

`config-tool/internal/roundtrip` keeps the source bytes and uses the yaml.v3 node tree only as
an index: node `Line`/`Column` positions map to byte offsets (`Column` counts runes). An edit
is a byte patch over a value's span. `Write` emits the BOM, the header, the patched body and
the trailing document markers, then re-parses its own output and compares it with the expected
tree. A mismatch is an error (`ErrPatchVerification`), never a file.

Without edits `Write` returns the input byte for byte. A test over the whole corpus, and a
fuzz target, pin that. A stream with more than one document is refused (`ErrMultiDocument`).

The library choice of ADR 0009 is unchanged; this record only fixes how the library is used.

## Consequences

- A loaded file round-trips byte-identically, and an edit touches only the bytes of the edited
  value.
- The package needs its own span scanner for the cases the node tree does not position
  exactly (block scalars, multi-line plain scalars, flow collections, the value after an anchor
  or a tag). The write self-check catches a wrong span before anything is written.
- Inserted keys follow the file's own indentation, line ending and dash style, so the patch
  code must detect them.

## Alternatives

- **Re-encode the `yaml.Node` tree.** The simplest code, but it fails the byte-identity bar on
  the corpus, and every save would rewrite the user's file.
- **A hand-written YAML parser that keeps all trivia.** Full control over bytes, but a second
  YAML implementation to maintain next to the one Helm uses, with its own spec gaps.
- **A line-based text editor without a parse tree.** Cannot tell a key from the same text in a
  block scalar or a comment, and has no way to check the result.
